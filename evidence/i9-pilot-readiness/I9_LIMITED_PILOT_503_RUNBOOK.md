# I-9 — памятка по HTTP 503 для ограниченного пилота

**На утверждение.** Применимость ограничена отдельно разрешенным синтетическим пилотом на точном выбранном SHA. Два исторических HTTP 503 остаются **UNKNOWN, объяснено 0/2**. Современные проверки показывают несколько возможных путей отказа. Первичные причины обоих прежних событий неизвестны. [Матрица отказов PR №12](https://github.com/IskhakovMA/fixes/blob/f02400c16139293b8470f5c03bbafe1293b2a69c/evidence/i9-d8-503/2026-11-25/I9_HTTP_503_DECISION_MATRIX.md)

## Действия оператора

| Наблюдение | Порядок |
|---|---|
| Защищенный GET 503 | Зафиксировать время, выбранную версию и безопасный код. Проверить готовность сервиса и разрешенность запроса. После подтвержденного восстановления сделать один свежий авторизованный GET с актуальным scope и, где требуется, новым snapshot/cursor. Повторный отказ передать ответственному. При отказе выпуска старый ответ или обход admission не использовать. |
| GET 409 | Для `PATIENT_QUERY_CHANGED` получить новый авторизованный снимок по контракту маршрута. При `ACCESS_CONTEXT_CHANGED` или 401 остановиться и восстановить подтвержденный контекст доступа. Утрата scope (403/404) требует прекратить обращение к объекту. |
| Запись отказала до COMMIT с подтвержденным rollback | Перечитать доступное состояние и актуальную версию. Новый явный запрос допустим только если действие по-прежнему требуется и контракт маршрута разрешает повтор с подтвержденной версией. |
| COMMIT подтвержден, ответ потерян | Перечитать состояние. Новую мутацию не инициировать. При необходимости подтверждения результата использовать предусмотренный маршрутом явный replay с прежними действующим ключом и точным телом, для того же действия и при актуальных правах. |
| COMMIT UNKNOWN, в том числе после 503, тайм-аута или обрыва | Немедленно остановить повтор. Сверить доступное состояние и версию свежим авторизованным чтением. При неясном результате, несогласованности состояния или утрате прав передать ответственному. Автоматический повтор PATCH/POST и новый ключ для той же попытки исключены. Явный same-key replay допустим только для конкретного маршрута с документированной гарантией и подтвержденным действующим ключом. |
| Публичный Quality возвращает `QUALITY_NOT_AVAILABLE` | Штатный закрытый доступ. Ждать утвержденного изменения режима. |

Для `POST /api/patients` replay использует ровно прежний ключ и тело, того же аутентифицированного сотрудника и операцию. На точном B1 права проверяются заново и повтор аудируется. Прежний ключ с другим телом отклоняется. Успех контрольного GET сам по себе не доказывает, что предыдущий COMMIT или доставка ответа состоялись. [Контракт создания B1](https://github.com/IskhakovMA/fixes/blob/3a0cb5db434032b3f7b6370c305c558a4b5d331c/backend/app/services/patient_create.py#L100-L145)

## Эскалация

- Первый неизвестный исход записи, отсутствие ожидаемого обязательного аудита или несовпадение состояния и версии — остановить этот сценарий. Зафиксировать инцидент и передать ответственному до следующей записи.
- Повторяющийся некодированный 503 либо признаки выдачи вне scope, потери аудита или несогласованной записи — приостановить пилот, сохранить разрешенные технические квитанции и запросить решение владельца. Порядок возобновления и эксплуатационные пороги утверждаются до старта.
- Использовать защищенный канал. Квитанция минимальна: версия, UTC, шаблон маршрута без параметров, метод, статус приложения и proxy при наличии, безопасный код, состояние COMMIT/rollback/unknown, стадия доставки и результат разрешенного контрольного чтения. Анонимная случайная корреляция используется, если она уже разрешена. В журнале не должно быть тел, SQL, токенов, медицинских данных или идентификаторов. Новые поля и срок хранения утверждаются отдельно. [Проект телеметрии](https://github.com/IskhakovMA/fixes/blob/f02400c16139293b8470f5c03bbafe1293b2a69c/evidence/i9-d8-503/2026-11-25/I9_HTTP_503_TELEMETRY_PROPOSAL.md)

## Три независимых решения

| Область | Статус | Что требуется для изменения |
|---|---|---|
| Отдельный Draft PR B1 | **NO-GO без отдельного решения владельца** | Принятая матрица точного SHA, явное разрешение владельца на PR, перечень открытых обязательств и проверенный запрет продвижения до их закрытия. Вариант B по историческим 503 относится только к рассмотрению указанного Draft PR, пока не принято отдельное решение о пилоте. |
| Ограниченный синтетический пилот | **Готовить в согласованных границах. Запуск требует отдельного разрешения** | Назначить ответственного и срок, согласовать точный SHA, синтетическую базу, допустимые браузеры/роли и пределы нагрузки, D8 по фактически включенным платформам, безопасные повторы, стоп/эскалацию, откат и наблюдение. Не считать приемку пилота основанием открыть PR. |
| Production или реальные медицинские данные | **NO-GO в рамках I-9** | Отдельно пройти Real-Data Gate, принять эксплуатационный профиль на целевой инфраструктуре, HTTPS/хостинг/контроль доступа, бэкап и восстановление, RPO/RTO, аудит и retention, privacy/legal и регламент инцидентов. [Real-Data Gate](https://github.com/IskhakovMA/fixes/blob/3a0cb5db434032b3f7b6370c305c558a4b5d331c/PILOT_READINESS_REVIEW.md#L516-L575) |
