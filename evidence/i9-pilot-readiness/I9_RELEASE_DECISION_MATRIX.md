# I-9 — границы допуска

Кандидат B1 `3a0cb5db434032b3f7b6370c305c558a4b5d331c`. Постоянный History test-only `b4b1661ec6359800bfd700405b73b03f6c46b30d` проверен отдельно. Выбор между ними для конкретного решения требует точного SHA. Предыдущая [приемочная матрица WP-I](https://github.com/IskhakovMA/fixes/blob/33c29c669ceee93c05cbe4968d789e0ec723c137/evidence/i9-operational-acceptance/I9_FINAL_ACCEPTANCE_MATRIX.md) сохраняет связь с исходными требованиями.

| Уровень | Статус | Необходимые доказательства и решение |
|---|---|---|
| **Draft PR, только ревью** | **NO-GO** | Сверить дерево и доказательства выбранного SHA. Владелец может отдельно разрешить review-only Draft PR с перечнем открытых performance и D8, выбрав условие B по 503, указав ответственного, срок и процедуру эскалации. Такой Draft служит площадкой для ревью, с явным запретом merge/deploy, пробного запуска на реальных данных и заявления о приемке. Вариант A по 503 сохраняет блокировку. Текущее решение сохраняется до явного разрешения владельца. |
| **Ограниченный синтетический пилот P** | **NO-GO к запуску пилота. Техническая подготовка выполнена частично.** | Утвердить нагрузку и пороги, профиль стенда, состав ролей и платформ. На точном SHA получить результаты подтверждающего замера, 409 UI, audit/manifest/RBAC, ручные D8 в согласованных средах. Windows остается обязательной при включении Windows в область пилота, аналогично физические мобильные устройства. Назначить ответственного, канал инцидентов, срок и критерий остановки. Выбор B для Draft PR не покрывает пилот. |
| **Production / реальные медицинские данные** | **NO-GO** | Отдельный Real-Data Gate, утвержденная инфраструктура, инженерные и медицинские владельцы, HTTPS, права и защищенное хранение, подтвержденное восстановление и RPO/RTO, retention, телеметрия и работа с инцидентами, проверенный rollback и отдельное согласование rollout. Синтетический P подтверждает только указанную область эксперимента. |
