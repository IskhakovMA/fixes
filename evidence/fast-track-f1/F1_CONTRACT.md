# Sprint F1. Контракты двух новых маршрутов

Продуктовая основа — I-9 `b5b408fe411f4431042eced96f0801cffb577a83`. Изолированная feature-ветка зависит от этой версии. Для ссылок с существующих экранов использованы действующие правила браузерной навигации и текущего доступа.

| Экран | Серверный источник | Что видит пользователь |
|---|---|---|
| Пульс клиники | `GET /api/analytics/summary`, серверный параметр этапа | Доступные записи реестра, просроченные события, замечания к качеству данных, обязательные пункты, очередь уведомлений и пациенты с активной отметкой внимания. Показаны серверное определение, область доступа, дата и время расчета. |
| Проблемная зона | `GET /api/analytics/details`, тип показателя, тот же этап, limit/offset | Серверная выборка по выбранному показателю, по 20 строк. Количество обязательных пунктов в сводке и количество пациентов в детализации имеют разные единицы. Переход к конкретной карточке снова проверяет объектный доступ. |
| Мой день | `GET /api/patients?view=page`, `GET /api/patients/workspace/events`, `GET /api/patients/workspace/checklists` | Текущий этап и лечащий врач, доступный плановый срок и активная отметка внимания, подтвержденные плановые события без факта и обязательные пункты. Реестр поддерживает фильтр срока. Для списков с серверными курсорами размер страницы 20. |
| Карточка и целевой раздел | `GET /api/patients/{id}` через действующий `openPatient` | Свежие разрешенные данные, переход в соответствующую вкладку, проверка существования выбранного события, возврат к источнику и браузерный Back/Forward. Клинические действия выполняются на существующих вкладках с прежними проверками. |

Пульс доступен ролям developer, department_head, deputy_chief_oncology и caop_head. «Мой день» доступен роли doctor. Клиентская видимость управляет навигацией. Сервер проверяет scope и выдачу каждой записи на прежних эндпоинтах.

Загрузка и ошибка очищают прежнюю выдачу. После закрытия экрана остаются только параметры выбора в рамках той же сессии; навигация загружает данные заново. При истечении, смене доступа или личности сбрасываются состояние и отображаемые данные. Разрешенный обычный конфликт реестра может вызвать один новый запрос первой страницы, смена доступа идет через повторную авторизацию. Пульс при конфликте показывает явное обновление. Выбор фильтра, переход и восстановление не создают клинических записей. Нет загрузки полного реестра, клиентской медицинской формулы или хранения данных в браузерном storage. Реальная SQLite v33, RBAC, data_version, release admission, read-audit/manifest и клинические правила сохранены.

Ограничения источников: «Мой день» показывает имеющиеся плановые сведения и активные причины внимания. Сервис не вычисляет новое ближайшее медицинское действие и не выводит рейтинг лечения. Quality в управленческом маршруте использует действующий серверный класс `quality_actionable`. Прежние правила активации Quality v1 сохраняются.
