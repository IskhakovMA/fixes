## Два рабочих маршрута

- **Пульс клиники → проблемная зона → серверная выборка → карточка.** Шесть показателей с серверными определениями и временем расчета, фильтр этапа, постраничные результаты, переход в соответствующий раздел карточки. Доступ определяется прежней серверной областью. Явный возврат и браузерный Back/Forward сохраняют допустимый контекст той же сессии.
- **Мой день → пациент → текущий этап → плановое событие или обязательный пункт.** Лечащий врач, подтвержденные сроки, отметка внимания, незаполненные обязательные пункты и пустые состояния. По событию открывается разрешенная карточка и нужный участок маршрута. Отсутствующие плановые сведения обозначаются явно. [Точные API и семантика](F1_CONTRACT.md)

Единственное изменение runtime backend — два имени JS в существующем списке статических ресурсов. Медицинские маршруты, схема v33, RBAC и scope, admission/data_version, аудит, manifest и правила записи сохранены. Правила защиты CSP/XSS распространяются на оба новых скрипта. При разработке тест обнаружил 404 на еще не зарегистрированном ассете и проверку старого CSS-маркера; регистрация двух имен и сохранение прежнего маркера с суффиксом F1 устранили ошибки, адресный итог — 35/35.

В чистом checkout продукта `tools/tests/fast_track_f1/run.py` запускается locked Python 3.13. Установленный Playwright и совпадающий Chromium передаются через `PLAYWRIGHT_MODULE` и `PLAYWRIGHT_BROWSERS_PATH`; для axe требуется `AXE_SOURCE`. Параметр `--out` задает новый закрытый каталог вне worktree. Seed в `tools/tests/fast_track_f1/server.py` формирует пять карточек по фиксированным сценариям, даты рассчитываются относительно московского календарного дня. Идентификаторы и учетные данные создаются только на время теста. Runner проверяет нулевое изменение медицинских таблиц, штатное завершение, удаление SQLite и освобождение loopback. Опциональный `F1_SCREENSHOTS=1` сохраняет снимки разделов.

Для дополнительных отрицательных сценариев используйте `supplement-run.py <чистый F1 checkout> <новый закрытый каталог>` с тем же окружением, а контрольную фикстуру проверьте вызовом `verify_healthy_fixture.py <чистый F1 checkout>`. Публикуются только агрегаты; исходные журналы, браузерные сессии, временные базы и файлы доступа остаются частными.
