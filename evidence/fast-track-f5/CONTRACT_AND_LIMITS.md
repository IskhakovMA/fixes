# Fast Track F5 · контракт и границы

| Действие | Действующий API | Как использует F5 |
| --- | --- | --- |
| Перенос показателя из «Пульса» | `GET /api/analytics/summary`, `GET /api/analytics/dashboard` | Передает поддерживаемый этап и тип детализации. Значения и определения приходят с сервера |
| Аналитика из «Моего дня» | `GET /api/analytics/dashboard`, `GET /api/analytics/details` | Пациенты, просроченные события или пациенты с незаполненными обязательными пунктами в области вошедшего врача |
| Перелистывание аналитики | `GET /api/analytics/details?type=…&limit=50&offset=…` | На клиенте одновременно одна страница. Сервер определяет доступ, порядок и total. Если набор сократился и страница исчезла, выполняется один запрос первой страницы |
| Открытие и возврат | `GET /api/patients/{id}`, затем новый dashboard и details | Используется существующий объектный GET и навигационный guard. История держит только непривилегированный указатель на контекст в памяти. Фокус возвращается к доступной строке или заголовку |
| Клиническое действие в карточке | Действующий версионированный PATCH события | Явное действие сотрудника. Последующая аналитика заново читает сервер |
| CSV | `POST /api/analytics/export` | 6 видов отчетов. Для качества данных доступен разрез по кодам, для чек-листов по этапам. Интерфейс скачивает фактические серверные байты после проверки актуальности запроса |
| Ошибка доступа | Действующие 401, 403, 404 и `ACCESS_CONTEXT_CHANGED` | Поздние ответы устаревшего чтения подавляются, объект при 403/404 больше не предлагается до свежей выдачи. Механизмы реестра WP-H с `PATIENT_QUERY_CHANGED` и `CURSOR_EXPIRED` сохранены |

## Определения

- Применимые общие фильтры остаются серверными. Период хронологического графика берется из дат его серверных строк. Подпись показывает время расчета и часовую зону сервера.
- Список просроченных событий может содержать несколько строк на пациента. Счетчик пациентов с просрочкой и число событий имеют разные единицы. Счетчик незаполненных обязательных пунктов раскрывается списком пациентов с такими пунктами. Замечания качества, уведомления и пациенты также имеют отдельные единицы.
- У текущего показателя активных маршрутов серверный `patients` возвращает весь отфильтрованный и разрешенный набор пациентов. Интерфейс указывает это перед открытием списка. Точный drill-down только активных маршрутов потребовал бы отдельного серверного контракта.
- Существующий `/analytics/overdue` поддерживает фильтрацию плановых дат. F5 связывает текущие KPI с текущими деталями. Исторические состояния и медицинские оценки отсутствуют.
- Все существующие CSV отражают текущее состояние при выгрузке. Период графика не ограничивает CSV. Серверный отчет нагрузки ограничен 50 строками при действующем запросе.
- Offset-страницы читаются независимо. Между чтениями изменившийся набор может переставить строки. Подписанный cursor и атомарный снимок нескольких страниц относятся к другим контрактам.

## Границы эксплуатации

Production, ручная D8, недельное расписание, дефектура ЦАОП, Pilot P и исторические HTTP 503 ведутся отдельно. Оба исторических HTTP 503 остаются UNKNOWN.
