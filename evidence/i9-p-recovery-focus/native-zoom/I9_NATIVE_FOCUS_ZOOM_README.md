# Chromium. Нативный масштаб и восстановление после двух 409

Воспроизведение использует только точный исходный B1 с проверяемым изменением `static/app.js`, тестовый сервер WP-H и одноразовую базу на 1 000 синтетических пациентов. Chromium запускается в новом временном профиле. Разрешение extension `tabs` используется для нативного `chrome.tabs.setZoom` и обратной сверки `getZoom` текущей loopback-вкладки. Масштаб CSS и эмуляция pinch не используется.

Укажите vetted Playwright через `PLAYWRIGHT_MODULE`, поддерживающий extension полный установленный Chromium через `WP_H_FULL_CHROMIUM` и локальный axe-core через `AXE_SOURCE`. Запустите lock-версию Python B1. `CANDIDATE_CHECKOUT` указывает на временный checkout точного B1 с намеренным единственным diff `static/app.js`, `PRIVATE_OUTPUT` — на новый частный каталог вне checkout.

```sh
"$B1_PYTHON" -B run_native_focus_zoom.py "$CANDIDATE_CHECKOUT" "$PRIVATE_OUTPUT" --candidate
```

Оба режима темы проверяют нативные 100%, 200% и 400% (ширины 1280, 640 и 320 CSS px). Для каждого измерения нажимается Enter на пагинации. Настоящий сервер возвращает два 409, прежняя выдача скрыта и inert, а видимая кнопка явного обновления получает фокус и ссылку на описание ошибки. Смена фокуса Shift+Tab и Tab не добавляет GET. После снятия fault Enter на кнопке дает единственный явный GET с 200. Дополнительно проверяются горизонтальное переполнение, позиция кнопки во viewport, axe A/AA и ноль клинических записей.

Первый диагностический запуск остановился на сравнении дробного `getZoom()`: Chrome вернул для 400% значение `3.9999999999999996`. Исправление измерителя нормализует проценты так же, как существующая нативная проверка Quality, сохраняя проверку DPR и ширины. Сохранено положительное доказательство для шести сочетаний темы и масштаба. Результат Chromium учитывается отдельно от ручной проверки Safari/VoiceOver.
