# Клавиатурный фокус реестра после повторного 409

Продуктовая база `3a0cb5db434032b3f7b6370c305c558a4b5d331c`. Chromium 151.0.7922.34, реальный FastAPI, одноразовая SQLite v33 с 1 000 синтетических записей. Playwright отправлял реальные Enter, Tab, Shift+Tab и Escape. Ручного прослушивания VoiceOver в этом прогоне не было.

## До исправления и источник дополнительного GET

1. Сфокусированная кнопка «Следующая страница» получила Enter. Приложение перевело реестр в loading, старый контейнер стал inert.
2. Реальный запрос с курсором вернул 409 `PATIENT_QUERY_CHANGED`. Единственный автоматический перезапрос без курсора вернул тот же 409 на том же read version 2 и session epoch 0.
3. Старый реестр скрыт и inert, `aria-busy=false`. Соседнее предупреждение с `role=alert` и доступной кнопкой появилось, а фокус упал на BODY. После 60 реальных Tab фокус до нее не дошел.
4. После терминального 409 последовательность ввела Chromium в chrome‑фокус и вернула в окно. Пара `window.blur`/ `window.focus` произошла при остающейся `visible` вкладке. Код `revalidateVisibleWorkspace → reconcilePeerSession → resumeSession` после проверки `/api/auth/me` отправил ровно один дополнительный GET без курсора. В трассе fetch это `Object.resumeSession`, epoch 1, read version 2, `dirty=false`. У маршрута пагинации два GET, у перепроверки сессии отдельное чтение.
5. В продолжающем действовать режиме синтетической ошибки дополнительный GET сам получил 409. Предыдущее восстановление сессии уже открыло скрытую до этого форму входа, и дальнейшие Tab обходили ее поля. Фиксация fetch и событий фокуса не вмешивалась в маршрутизацию или содержимое ответов.

## Изменение

Смена фокуса начинается только из реально сфокусированного pager. Синхронно до включения inert выбран видимый заголовок реестра. Первая потеря фокуса навсегда снимает владение этим переходом. После ответа успешное чтение возвращает статус страницы, а терминальный `PATIENT_QUERY_CHANGED` — видимую доступную кнопку «Обновить список», связанную с текстом предупреждения через `aria-describedby`. Оба завершения проверяют текущий epoch, поколение навигации и read version. Старый callback не меняет фокус; запрос удаляет только свой pager lock. Обновление происходит по явному Enter оператора. ## После исправления

14 случаев прошли, каждый с нулем незапланированных медицинских записей. У терминального двойного 409 на 1440 в светлой теме и 390 в темной теме ровно два автоматических GET, фокус уже на кнопке; Shift+Tab затем Tab возвращает на нее. После Enter явного обновления реестр снова готов. Axe A/AA этих двух ошибок: 0 нарушений.

| Вариант | Наблюдение |
|---|---|
| Сервер 409 → 200 | Два GET, доступная новая выдача, фокус у статуса страницы. |
| Двойной серверный 409 | Два GET, старая выдача скрыта и inert, фокус у retry. Оба 409 без массива пациентов. |
| Пользователь переводит фокус и при необходимости возвращается вручную | Фокус остается в фильтре либо на вернувшемся заголовке. |
| Открытый модальный диалог | Фокус остается внутри; Escape закрывает диалог. |
| Смена раздела и задержанный реальный HTTP 200 | Фокус не возвращается к старой пагинации. Back восстанавливает реестр, Forward возвращает календарь. |
| Реальный 409 → 401 | Стенд отозвал сессию через обычный logout между ответами. Фокус на форме входа. Повторный вход и новая клавиатурная пагинация прошли. |
| Инъекции 401 и ACCESS_CONTEXT_CHANGED | Фокус на форме входа, дополнительного pager retry нет. |
| Инъекции CURSOR_EXPIRED 410 и transport timeout | 410 → 200 за два чтения; транспортный сбой конечен. |
| Повторный Enter в ходе запроса | Выдано ровно два GET при двойном 409. |
