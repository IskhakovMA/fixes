# Дополнительное чтение после терминального 409

В чистом B1 реестр получает два серверных ответа `409 PATIENT_QUERY_CHANGED` с помощью детерминированной гонки на временной синтетической SQLite. После обработки второго 409 старая таблица и пагинация становятся hidden/inert, действие восстановления становится доступным в DOM, а фокус остается на BODY вместо явной кнопки. Существующий обработчик фокусирует статус только при успехе.

До начала дальнейшего обхода браузер зафиксировал **2 GET** с кодами 409 → 409. Зафиксированные стеки обоих запросов ведут через `loadPatients → changePatientPage`, первый URL содержит курсор, второй — без него. После выхода Tab в интерфейс браузера документ фиксирует window blur и затем window focus, при неизменной visibility visible. За этим идут перепроверка сессии, смена epoch 0 → 1 и **1 отдельный GET** первой страницы из `resumeSession`, без курсора. Серверная инъекция продолжала действовать и на этот запрос, поэтому он тоже получил 409; пользователь оказался в оболочке повторной авторизации. Этот третий наблюдаемый HTTP относится к восстановлению контекста при фокусе окна. В цикле пагинации остаются ровно два HTTP.

Изначальная архивная трасса не записывала стек GET. Повторное воспроизведение той же последовательности на чистом B1 с инструментированием подтверждает путь дополнительного чтения в новом воспроизведении. Нет основания менять независимую проверку сессии при возврате фокуса. В отчетах разделены счетчики терминальной пагинации, обхода фокуса и явного пользовательского обновления.
