# ADR I‑9 — история навигации

Статус: предложено для независимой приемки. Кандидат 72dad18c11feb8d9d8b62b702b05f54ed7ffad1d. Продуктовый diff отсутствует.

## Контракт и решение

- URL содержит только разрешенные идентификаторы экрана и вкладки. Пример: `?screen=patient&tab=overview`. Не включать идентификатор пациента, ФИО, поисковый ввод, значение черновика, версию клинической записи или секрет сессии.
- У записи `history.state` есть версия формата, индекс записи, nonce сессии и непрозрачный идентификатор маршрута. Отображение маршрута на объект остается только в памяти текущего документа. После перезагрузки или при неизвестной записи выбрать разрешенный реестр, очистить пациентское представление и заменить текущую внутреннюю запись истории. Пациента по URL не читать.
- Для обычного клика фиксировать переход только после явного решения по черновику и проверки доступа. Для `popstate` запретить применение чужой записи. При отказе пользователя вернуть индекс прежней внутренней записи через `history.go(delta)` с одноразовым подтверждением коррекции. Сохранить Forward и текущее содержимое. Выход за границы документа остается штатной навигацией браузера.
- При любой навигации сверять действующую личность, эпоху сессии и доступ к целевому экрану. Для карточки получать объект существующим авторизованным и аудитируемым GET. Применять ответ только для текущего намерения и действующего пользователя, без мерцания чужой карточки. Очередность навигации независима от номера чтения деталей. При 403/404, отзыве объекта или смене пользователя очистить маршрут, данные и связанные токены, вернуть разрешенный реестр. Объектный отказ возможен без смены эпохи.
- Использовать существующее подтверждение клинического перехода. Предложение не вводит автосохранение и не заменяет правила клинической версии. Повторный вход и пересборка интерфейса не создают промежуточных записей истории. Обработчик истории подключается один раз на документ. История не повторяет медицинские записи.

## Условия независимого ревью

1. Реальные клики реестр → карточка → все восемь вкладок, затем браузерные Back/Forward. Сверить URL, доступный экран, выбранную вкладку и фокус. Отдельно проверить календарь и аналитику.
2. Черновик в поле и форме создания. Проверить отказ и согласие на переход, быстрые противоположные переходы, Forward после отмены, незавершенное сохранение и отсутствие автоматических медицинских запросов.
3. Перезагрузка, bfcache, истечение и смена сессии, отзыв объекта без смены сессии, старый ответ GET после нового намерения, 403/404 и текущий контракт 409. При переходе к внешнему документу проверить штатное поведение.
4. Сверить отсутствие PHI и секретов в URL/history.state, существующую семантику RBAC и аудита чтения. Технический auth/activity учитывается отдельно от медицинских записей.
