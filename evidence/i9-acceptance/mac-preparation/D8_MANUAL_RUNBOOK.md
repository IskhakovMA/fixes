# D8 — ручной прогон и квитанции

Статус всех строк OPEN. Только изолированный синтетический стенд exact SHA. До входа подтвердить отсутствие клинических данных и подключений к production. Использовать Python 3.13, проверенный lock `backend/requirements-dev.txt` и штатную локальную синтетическую фикстуру проекта. Зафиксировать контрольную сумму исходного стенда и шаблона данных. Актуальное руководство не меняет публичный допуск Quality v1. Лабораторный bounded Quality включается только изолированной тестовой настройкой, если оператор уполномочен. Файлы с учетными данными, DB/WAL/SHM и сырые сетевые дампы в доказательства не входят.

## macOS и Safari + VoiceOver

1. Включить VoiceOver через Command+F5. В настройках Safari включить полную клавиатурную навигацию и записать ее состояние. VO+стрелки проходят элементы, VO+Shift+Down/Up входят и выходят из групп, VO+Space активирует. Выполнить отдельно обычные Tab и Shift+Tab. При перехвате стрелок отключить Quick Nav на проверке виджета.
2. Через Page Zoom выставить реально доступные 100/200/400%. Записать показанное значение, CSS ширину и DPR. Неподдерживаемый масштаб записать OPEN. Обе темы фиксируются отдельными квитанциями.

## Windows и Firefox + NVDA

1. Запустить NVDA и открыть Speech Viewer через Tools. Browse mode используется для структуры и объявлений. Tab/Shift+Tab проверяют фактический фокус. NVDA+Space переключает focus mode для Arrow/Home/End. Записать настройки клавиатуры и режим.
2. В меню Firefox Zoom проверить 100/200/400%, выключив Zoom Text Only. Ctrl+0 возвращает 100%. Эмуляция ширины не считается нативным масштабом или проверкой реального мобильного устройства.

## Шаги каждой квитанции

- **D8-01:** skip link, landmarks, меню, закрытый drawer. Проверить порядок Tab, видимый фокус, Escape и возврат, фон модального окна и reduced motion.
- **D8-02:** реестр → карточка → обзор, уведомления, данные, комментарии, события и даты, чек-лист, заметки, история. Проверить объявление ключа вкладки, selected и названия панели. Для истории проверять дату и статус, которые фактически представлены. Отдельно Arrow/Home/End, Enter/Space и разрешенные действия. Проверить read-only.
- **D8-03:** фактические кнопки браузера Back/Forward, включая вход из календаря и аналитики. Сверить URL, объектный доступ, вкладку, фокус, отказ/согласие при черновике и отсутствие клинических записей.
- **D8-04:** создание пациента, форма консилиума, аналитика/администрирование. Проверить имя диалога, связь ошибок с полем и summary, работу trap только внутри modal, Escape и возврат. Проверить отказ закрытому доступу.
- **D8-05:** потеря сети при незавершенном вводе, 409, повторный вход после 401, объектный отзыв, смена личности в соседней вкладке. Проверить текст ошибки, отсутствие автоматической записи, чужой карточки и переноса черновика.
- **D8-06:** Quality на синтетических 50 строках. В обеих темах и на каждом нативном масштабе проверить ширину, отсутствие лишнего переполнения и реальный Tab по точно именованным действиям в порядке выдачи. После последней строки проверить переход к «Далее» и Shift+Tab обратно. Axe фиксировать отдельно.
- **D8-07:** поддерживаемые мобильные 320/375/768 CSS px и desktop 1440. Проверить реальный тип устройства, ориентацию, drawer, длинные названия и сообщения, видимость действий. Результат эмуляции указывать отдельно от реального устройства.

Для каждого сценария, браузера, темы и масштаба создать отдельную строку `D8_RECEIPTS.tsv`. Записать ожидаемое и фактическое, дословное очищенное озвучивание, фокус, точные версии, роль, дату и ссылку на безопасное свидетельство. PASS требует фактического исполнения. FAIL требует наблюдаемого несоответствия. BLOCKED применяется при попытке без доступа к стенду. OPEN сохраняется для неручного или еще не исполненного сценария.

## Подготовка локального стенда

В изолированном checkout открытого на ревью SHA на macOS либо в разрешенной Linux-среде для Windows:

```sh
test "$(git rev-parse HEAD)" = 72dad18c11feb8d9d8b62b702b05f54ed7ffad1d
python3.13 -m venv .venv-d8
.venv-d8/bin/python -m pip install --require-hashes -r backend/requirements-dev.txt
.venv-d8/bin/python -m pip check
umask 077
d8_lab_dir=$(mktemp -d)
chmod 700 "$d8_lab_dir"
.venv-d8/bin/python tools/tests/wp_i_quality/lab.py --port 18889 --count 240 \
  --fixture-file "$d8_lab_dir/fixture.json" --scratch-dir "$d8_lab_dir"
```

В отдельном терминале проверить HTTP 200 от `http://127.0.0.1:18889/healthz`. В браузере открыть `http://127.0.0.1:18889/` и войти синтетической ролью из owner-private fixture. Для Windows использовать допущенный Linux-стенд с подтвержденной доступностью локального адреса из Firefox на Windows. Проверить подключение командой `Test-NetConnection 127.0.0.1 -Port 18889`. Если локальный доступ отсутствует, записать BLOCKED и согласовать изолированный адрес с владельцем. Нативный Windows-запуск Python-лаборатории не подтвержден.

Только для D8-06 и только на проверенном локальном синтетическом origin оператор запускает лабораторное подключение Quality, эквивалентное `setupBounded()` из `tools/tests/wp_i_quality/browser_helpers.cjs`, передав `qualityPath` из текущей fixture. Затем закрывает инструменты разработчика и проверяет обычную навигацию. Для проверок 401/409/revoke нужен согласованный сценарий fixture. Если оператор не может достоверно создать состояние, соответствующий сценарий остается OPEN. Завершить лабораторию штатным Ctrl+C. Файлы профиля, временную fixture и SQLite не включать в квитанции.
