# Clinic Tracker — WP-I / I-9, матрица приемки Back/Forward

**Готово к независимой приемке.** База `20aa7ae3431a29ae08016cbc660400fb700b935a`, проверенный HEAD `29cd16d1d37f008467e449aa573df78f7b7a7970`. Интеграцию не выполняли.

[Уточненный ADR](https://github.com/IskhakovMA/fixes/blob/29cd16d1d37f008467e449aa573df78f7b7a7970/docs/ADR_I9_BACK_FORWARD.md) фиксирует согласованное решение для неизвестной записи истории. Обычный Back/Forward работает по доверенным индексам. При неизвестной позиции приложение предлагает решение по черновику. «Остаться» сохраняет текущую форму и исходную версию после проверки сессии и свежего аудитируемого GET. Явное подтверждение позволяет удалить черновик и вернуться в реестр. Новый индекс сегмента устанавливается заменой текущей записи. Относительное смещение между сегментами не вычисляется.

Идентификаторы пациентов, черновики, поисковые запросы и секреты не передаются в URL или историю. Восстановление не запускает медицинские записи. Браузерный отчет содержит структурированные трассы реальных действий с синтетическими данными. Архив включает семь сверенных квитанций, метаданные прогонов и этот документ. Снимки DOM, сырые HTTP-тела, куки и тестовые credentials исключены.

Независимые направления проверили архитектуру, UI и черновики, безопасность и браузерные доказательства. Прошлые прогоны сохранили обнаруженные регрессии. Исправлены асинхронный фокус, блокировка перехода при немутирующем чтении, показ прежних строк до авторизованной перезагрузки реестра и тестовые барьеры смены эпохи и завершения отбрасываемого ответа. [Промежуточный прогон](https://github.com/IskhakovMA/fixes/actions/runs/45447062566)

Профиль нагрузки, критерии performance gate и ручной D8 остаются открыты. Два исторических HTTP 503 без прикладного кода сохранены как отдельный риск. Медицинский backend, RBAC, аудит, GQ-M2, SQLite v33, production и допуск публичного Quality v1 не изменялись. WP-J остается отдельным этапом.
