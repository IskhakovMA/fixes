## Маршрут врача

«Мой день» открывает все разрешенное расписание или запускает поддерживаемый сервером поиск по имени пациента из выбранной строки. Такой поиск может вернуть несколько событий, поэтому действие оставляет выбор за врачом. Список показывает пациента, этап, плановую дату, время либо его отсутствие, заведующего из разрешенного ответа и действие. Просрочка, сегодня и будущая дата визуально различаются по календарному дню организации.

`GET /api/patients/workspace/events` сохраняет серверную сортировку, cursor и patient scope. Открытие события сверяет ID, вхождение этапа, дату, время и отсутствие факта по свежей разрешенной карточке. При возврате поиск и допустимый курсор используются для нового чтения. Если событие есть в свежей странице, фокус возвращается на его действие. После изменения или потери доступа список перечитывается. При истекшем курсоре или обычном конфликте выполняется один контролируемый переход на первую страницу. Смена субъекта, истечение сессии и отзыв доступа очищают прежнюю выдачу.

Синтетический прогон получил 58 уникальных разрешенных событий на страницах 50 и 8 с сохранением серверного порядка. Прогон подтвердил текущее событие без времени, будущие и просроченные события, отсутствие чужой записи, Back/Forward второй страницы и позднее уточнение объекта. Во время записи штатный guard отклонил переход. Единственный явный версионированный PATCH факта подтвержден с аудитом. После свежего чтения событие исчезло из расписания и «Моего дня». Контрольное переназначение во второй сессии проверило реальный нейтральный 404, а отзыв сеанса — реальный 401. `CURSOR_EXPIRED` и двойной 409 в новом наборе отмечены как транспортные инъекции.

## Внутренние уведомления

Действующие `/api/internal-notifications/*` определяют входящие, прочтение и счетчик. При наличии точного идентификатора события выполняется свежий объектный GET. Совпадение имени или даты само по себе не выбирает событие. Для доработки консилиума дополнительно проверяется соответствующая запись в существующей авторизованной выдаче. Для уведомлений без стабильного указателя на актуальный объект открывается разрешенная вкладка карточки без обещания точного выделения.

Открытие и возврат не отправляют POST прочтения. Даже когда карточка и вкладка уже открыты, переход из drawer заново проверяет событие, ставит фокус и сохраняет позицию History. Явное «Прочитано» выполняет один запрос через действующий API с CSRF, сверкой записи аудита и свежим серверным счетчиком. У завершенного события нет активного уведомления в обновленном списке. Внутренняя выдача и статусы отправки пациентам представлены отдельными вкладками. Баннер тестового SMS находится только в исходящих. В F4 отсутствуют новые внешние каналы доставки.
