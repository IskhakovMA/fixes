## Пользовательские маршруты

- **Врач** выбирает разрешенного пациента и явный свободный слот, проверяет сведения, сохраняет запись и открывает ее из расписания или списка. Поддерживаемые правки, перенос и повторная подача сохраняют серверные версии. После неопределенного ответа форма удерживает ввод и требует нового чтения.
- **Заведующий** использует расписание и записи в области своих отделений. Доступный набор определяет сервер. За пределами области занятый слот маскирует содержимое.
- **Председатель** открывает свежую запись, начинает рассмотрение, возвращает запись с обязательным комментарием или подтверждает подпись. История возвратов сохраняет раунд, автора, текст и даты. Отмена подтверждения подписи оставляет запись без изменения.
- **Авторизованная карточка** показывает доступные записи и подписанные снимки по точному идентификатору пациента. Ручная отметка решения ОК остается отдельным действием. Архив, восстановление, избранное, реестры и серверные XLSX используют прежние права и медицинские контракты.

## Проверенные гарантии

Сквозной сценарий на SQLite v33 подтверждает восемь ожидаемых медицинских операций, один подписанный снимок, один раунд доработки и девять точных манифестов чтения. Этап пациента после подписи сохранен. В отчете о контрактах отдельно описаны серверный rollback при отказе обязательного аудита, запрет изменения подписанного снимка и версия при переносе.

## Ограничения контракта

Для рассмотрения, возврата и подписи проверяется свежая доступная версия. Действующий сервер атомарно проверяет допустимое состояние и записывает аудит. Ожидаемая версия председателя внутри этой транзакции потребовала бы отдельного изменения API. Состояние после неопределенного ответа можно установить новым чтением. Прямую связь с конкретным COMMIT такое чтение само по себе не устанавливает.

Ручная Safari/VoiceOver D8 сохраняет статус NOT TESTED. Production NO-GO. Два исторических HTTP 503 остаются UNKNOWN.
