# Fast Track F6 · соответствие Staff-UX v2

| Рабочая область | Действующий контракт | Перенос F6 |
| --- | --- | --- |
| Расписание | `GET /api/consilium/schedule`, `/meta`, `/appointments`. Маскирование чужих слотов и признак `bookable` приходят с сервера. | Сохранены даты, группы, поиск и действующие кнопки. Открытие записи ведет в правую панель на широком экране и полноэкранную панель на узком. |
| Доступные записи | Действующий scoped `/appointments`, одно общее состояние архива. | Включена существующая таблица для ролей записи. Название соответствует реальному scope врача, заведующего и разработчика. На телефоне поля имеют подписи. |
| Подробности и история | Авторизованный список с точным ID и `/appointments/{id}/revisions`. | При смене записи убираются прежние поля и действия. Текущий контекст, поколение чтения и сессия проверяются до показа ответа. |
| Запись и перенос | POST записи, PUT с ожидаемой версией, DELETE с версией. Повторная подача после исправления идет отдельным POST с версией. | Перенос и изменение доступны из панели там, где это разрешено. Подстановка данных пациента привязана к свежему GET. После потерянного ответа ввод сохранен, отправка заблокирована до явной проверки состояния. |
| Председатель | Действующие POST `review`, `return`, `sign`. Сервер атомарно проверяет состояние и записывает аудит. | Актуальная версия проверяется перед действием. Подпись требует отдельного подтверждения. История раундов и ограничения подписанных записей сохранены. |
| Архив, избранное, реестры | Действующие области, версия записи при архивировании, ролевые реестры и три серверных XLSX. | Используют общую панель. Существующие фильтры, ограничения, отметка направления и серверные выгрузки сохранены. |
| Карточка | Список записей консилиума сопоставляется с карточкой по `patientId`. Ручная отметка ОК имеет отдельный API. | В обзоре появилась явная загрузка доступных записей с чтением подписанного снимка. Escape возвращает в карточку. |

Подписание не переводит пациенту этап и не создает ручную отметку ОК. По результату GET после потери ответа можно установить текущее доступное состояние. Этот GET сам по себе не связывает состояние с конкретным запросом. Перенос, архив и удаление используют имеющуюся ожидаемую версию. Для действий председателя UI сравнивает прочитанную версию, а сервер выполняет атомарную проверку перехода. Проверка клиентской версии внутри той же транзакции потребовала бы отдельного серверного контракта.

F6 использует актуальные правила явных слотов WP2.3. Закрытие автоматического времени из демонстрационных сценариев и новые правила расписания в объем не входят. Сырой журнал с клиническими данными не входит в публичный пакет.
