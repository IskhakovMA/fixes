# D8 B1 — комплект оператора macOS

Этот комплект автоматизирует запуск одноразового стенда и чистую остановку. Проверки озвучивания, фокуса, нативного масштаба и браузерных действий выполняет человек.

1. Откройте терминал в каталоге комплекта. Подставьте абсолютные пути к уже подготовленным чистому B1 checkout и изолированному Python 3.13 venv с пакетами из lock-файлов B1. Запустите команду.

   ```bash
   "$B1_VENV/bin/python" -I -B d8_operator.py "$B1_CHECKOUT" --port 19089 --receipt ./D8_TECHNICAL_SESSION.json
   ```

   При занятом порте задайте другой непривилегированный порт. Для отдельной технической проверки без ручной сессии добавьте `--smoke` и новый путь квитанции. Launcher ожидает точный SHA `3a0cb5db434032b3f7b6370c305c558a4b5d331c`, чистый checkout и версии зависимостей из lock-файлов. Он запускает только одноразовую синтетическую SQLite, создает 240 записей и показывает локальный URL и приватный путь фикстуры. Если запуск не подтвердился, завершайте приемку этого сеанса с BLOCKED.
2. Откройте локальный URL в выделенном профиле Safari. Следуйте [16 ручным шагам](I9_D8_MAC_OPERATOR_STEPS.md). Заполняйте свою копию [Mac-квитанций](I9_D8_MAC_SESSION_RECEIPTS.tsv), оставив вложенный шаблон исходным. Синтетические логины и пароль из локальной фикстуры вводятся лично и исключаются из квитанций.
3. В исходном терминале остановите стенд Ctrl+C. При штатном завершении runner проверит освобождение порта и удаление всей временной директории с SQLite и фикстурой. JSON по `--receipt` создается только после этих проверок. Путь должен быть новым, предыдущая квитанция не заменяется. Если остановка не подтвердилась, верните сообщение BLOCKED тестировщику.

## Статусы

- macOS Safari + VoiceOver. 16 NOT TESTED до фактической сессии.
- Windows Firefox + NVDA. 16 BLOCKED без допущенной Windows-среды.
- Физическое мобильное устройство. 16 BLOCKED без подтвержденных устройства и изолированного транспорта.

[Полная неизмененная матрица платформ](I9_D8_B1_RECEIPTS.tsv). [Техническая квитанция исходного стенда](REFERENCE_TECHNICAL_SMOKE.json) доказывает только запуск и очистку на B1. В автоматический результат не включены ручные PASS и FAIL.

Для воспроизводимой технической проверки маршрутов без ручной сессии можно запустить на свежей фикстуре:

```bash
"$B1_VENV/bin/python" -I -B d8_route_smoke.py "$B1_CHECKOUT" --port 19089
```

Скрипт регистрирует два входа синтетических ролей и выполняет только чтения медицинских API. Он выводит набор технических меток и HTTP-статусов. Используйте [статус D8](D8_STATUS.md) и [проверку материалов](D8_PUBLICATION_REVIEW.md) при включении файлов в сводный evidence.
