# Воспроизведение нагрузочных мониторингов I-9

Использовать только отдельную лабораторную среду. Checkout A и B1 по полным SHA из performance matrix в разные detached worktrees. Проверить чистые backend/static и совпадающие backend/requirements.txt и requirements-dev.txt. Установить закрепленные зависимости в отдельный Python 3.13 venv. Передать абсолютные пути к точным A/B1 через --base и --candidate. Копия драйвера отличается только этим способом передачи путей. SOURCE_MAPPING.json связывает SHA исполнявшихся локальных инструментов и переносимой копии. Все четыре файла измерительных хуков сохранены побайтно. Нельзя направлять драйвер в рабочую установку или к медицинской БД. Локальный фактический тестовый путь и сырые логи в package не включены.

Из каталога `reproducer/exploratory-harness` запустить команду окружения Python 3.13:

    python -B execute.py explore НОВЫЙ_КАТАЛОГ --base "$A" --candidate "$B1"

До первого процесса execute пишет PLAN.json и PLAN.sha256. План фиксирует точные Git SHA, порядок A/B1, SHA синтетической фикстуры, hash источников и SHA заранее сгенерированных целочисленных смещений. Горячие ветки FastAPI остаются исходными. Только observer оборачивает моменты начала/завершения функций и проверяет соответствие аудит-манифеста фактически сериализованному ответу. Слот PATCH не повторяется. При неопределенном исходе истекающая цепочка продолжение не получает.

Для независимой повторной сверки сохраненных результатов запустить:

    python -B ../collect_v2.py КАТАЛОГ_С_КВИТАНЦИЯМИ

Публикуемый агрегат включает только технические счетчики, относительные времена, синтетический профиль, SHA и коды. Raw оставляется локально и проверяется по INDEX перед агрегированием. Выбор вторичного режима подтверждения фиксируется отдельно от exploratory. В исследовательской матрице 12 arms. В длинном holdout — 6 новых пар всего; пилот не входит в ресэмплирование.

    python -B execute.py confirm НОВЫЙ_КАТАЛОГ --base "$A" --candidate "$B1" --selected ../CONFIRM_SELECTION.json
    python -B ../collect_v2.py КАТАЛОГ_С_КВИТАНЦИЯМИ > CONFIRMATORY_MATRIX.json
    python -B ../confirm_stats.py CONFIRMATORY_MATRIX.json

Для dual-writer контроля использовать отдельную копию dual-harness и тот же подкомандный режим explore. Оба writer открывают собственные сессии, меняют разные синтетические карточки и получают одновременные предложенные слоты. Цепочки версий и audit сверяются отдельно у каждой карточки. Заключение относится к ограниченному ASGI эксперименту. Он не задает production SLO или статистическую оценку всех режимов.
