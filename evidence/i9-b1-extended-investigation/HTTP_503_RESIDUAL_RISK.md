# Исторические HTTP 503 и безопасные повторы

**OPEN, UNKNOWN 0/2.** Новых исходных данных для атрибуции обоих старых событий нет. В широком профиле 10000 зафиксированы HTTP 409 и незапущенные слоты, HTTP 503 не наблюдалось. Занятый слот не является ошибкой SQLite или HTTP. Обслуживание SQLite, writer timeout, обязательный аудит/manifest и admission могут привести к 503 при иных условиях. Эти пути не доказывают происхождение двух событий. [Форензика и матрица](https://github.com/IskhakovMA/fixes/blob/f02400c16139293b8470f5c03bbafe1293b2a69c/evidence/i9-d8-503/2026-11-25/I9_HTTP_503_DECISION_MATRIX.md)

| Наблюдение или доказанная фаза | Действие |
|---|---|
| Занятый клиентский слот до dispatch | Пометить как недоставленное предложение. Не учитывать как HTTP-статус |
| Защищенный GET получил 409 или подтвержденный предвыпускной 503 | Проверить статус сервиса, сессию и область доступа. Свежее чтение по действующему контракту snapshot/cursor. Защищенный ответ удержан в проверенных сценариях |
| Клиническая запись, доказанный rollback до COMMIT | Перечитать разрешенное состояние и версию. Явный повтор в рамках правил маршрута при подтвержденных правах |
| Подтвержден COMMIT, клиент потерял ответ | Перечитать состояние, не создавать новую запись. Действующий replay допускается только с теми же ключом и телом, той же операцией и актуальными правами |
| COMMIT UNKNOWN | Свежее авторизованное чтение и проверка версии. Без подтвержденного исхода или документированного replay остановить операцию и передать дежурному. Автоматические PATCH и POST не допускаются |
| Закрытый публичный Quality возвращает кодированный 503 | Штатный gate. Ждать разрешения и изменения состояния по действующему протоколу |

Повторный некодированный 503 на клиническом изменении или потеря подтверждения с UNKNOWN COMMIT открывает отдельный инцидент. Минимальные будущие метаданные: случайный correlation ID, UTC и монотонная длительность, SHA, метод и allowlist шаблонов маршрутов, отдельные статусы приложения и proxy, безопасный класс и числовой SQLite-код, подтвержденный BEGIN/COMMIT/rollback/unknown, состояние обязательной пары audit/manifest и факт передачи ответа. ASGI send не доказывает получение клиентом. Отдельный ограниченный канал без SQL, содержимого, медицинских идентификаторов и секретов, с согласованными доступом, сроком хранения и эскалацией.

Владелец может оставить блокер или отдельно письменно принять риск для конкретного SHA после других gates, с подтвержденной процедурой повторов и ответственностью. Это сохраняет UNKNOWN и не дает оснований для production GO.
