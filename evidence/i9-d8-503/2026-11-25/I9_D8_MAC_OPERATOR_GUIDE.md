# D8 — Safari и VoiceOver

База `f849b2909c2d23923e0ce996f0aca4b670ca9c18`. Эти инструкции описывают ручную приемку на синтетическом стенде. Каждый PASS требует операторской квитанции.

## Стенд и предварительная проверка

1. Подготовьте отдельный чистый checkout точного SHA и Python 3.13 с lock-файлами по [короткой инструкции](D8_QUICKSTART.md).
2. Запускайте `bash stand/launch-d8.sh` из каталога evidence, передав абсолютные пути созданного checkout и venv. Mac использует 18889. Windows использует собственный изолированный WSL2 на 18890. Для физического устройства сначала подтвердите разрешенный транспорт.
3. На стороне браузера проверьте, что `D8_URL` — адрес `http://127.0.0.1` с нужным портом и открывается `/healthz`. Сверьте квитанцию запуска с SHA, происхождением и признаком синтетических данных. Проверьте состояние отключенных AI, mock-провайдера уведомлений и ограничения внешней сети по квитанции стенда. Работайте в отдельном чистом профиле браузера, выключите синхронизацию и внешние расширения. При недоступном loopback или неподтвержденной изоляции прервите сеанс и укажите `BLOCKED`.
4. Входите только под синтетическими разработчиком с ключом роли `developer`, врачом с ключом роли `doctor`, заведующим с ключом роли `head` либо врачом другого отдела с ключом роли `hiddenDoctor`. Локальный файл фикстуры содержит сопоставление ключей ролей с временными учетными записями в поле `accounts`. Для обычных сценариев выберите `Синтетика I8A3 00000` из реестра или поиска. Временный пароль прочитайте из `D8_FIXTURE_FILE` на машине стенда. Временный пароль можно вывести только в приватном терминале оператора командой `python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["password"])' "$D8_FIXTURE_FILE"`. Не копируйте вывод в квитанцию. Для операторских доказательств фиксируйте только роль и нейтральную метку фикстуры. Явные записи, необходимые определенной строке D8, выполняйте только над синтетической записью в одноразовом экземпляре. Вкладку отправки пациентам проверяйте чтением, без отправки. Результаты тестов разных платформ храните раздельно. Повторно запустите свежий экземпляр после смены прав или тестовых изменений, способных повлиять на следующую строку.
5. Для оценки отсутствия повторной отправки запишите только метод, тип операции, количество и HTTP-статус из вкладки Network или очищенного аудита на стенде. Отдельно отметьте чтения аудита. Для действий навигации ожидается ноль медицинских операций записи. Для явно разрешенной синтетической записи ожидается ровно одно соответствующее изменение, подтвержденное перечитыванием. Не сохраняйте сырой HAR, заголовки, тела ответов, cookies, содержимое History API, SQL-файлы, пароли или идентификаторы записей. Завершайте лабораторию сочетанием Ctrl+C после сохранения очищенных квитанций.

## Сессия macOS / Safari + VoiceOver

Откройте `http://127.0.0.1:18889/`. Включите VoiceOver через Command+F5. Включите в Safari режим перехода клавишей Tab по всем элементам веб-страницы и запишите настройку. Используйте VO+стрелки для чтения, VO+Shift+Down/Up для входа в группу или выхода, VO+Space для активации. Проверяйте Tab/Shift+Tab отдельно от курсора VoiceOver. При проверке меню вкладок выключите Quick Nav, если он перехватывает стрелки. В desktop-профиле фиксируйте ширину около 1440 CSS px при 100%, обе темы и состояние reduced motion. Для Quality меняйте нативный Safari Page Zoom до реально доступных 100/200/400%. Зафиксируйте точное значение меню, CSS-ширину и DPR. Если значение отсутствует в данной версии, оставьте этот подпрофиль OPEN.

Квитанцию на macOS заполняет оператор после фактической проверки озвучивания. Отдельно проверьте чтение landmarks и режима вкладки через ротор VoiceOver. Не перенаправляйте звук из реальной рабочей среды.

## Заполнение квитанций

В `I9_D8_RECEIPTS.tsv` 48 исходных строк для 16 сценариев и трех платформ. Для каждого фактически проверенного сочетания темы, роли, реального нативного масштаба, размеров, режима и устройства скопируйте исходную строку и укажите `subcase`. В `actual` укажите наблюдаемый итог, `spoken_redacted` содержит точное очищенное озвучивание, `focus_result` содержит последовательность фокуса и итоговую позицию. Укажите точные версии OS, браузера, screen reader, UTC-время и ссылку на очищенное доказательство. Поле `observed_route_redacted` допускает только экран, таб и пометку о непрозрачном маршруте без самого значения. Поле `writes_result` допускает только обезличенный тип, счетчик и статус.

| Статус | Когда ставить |
|---|---|
| NOT TESTED | Ручная проверка или часть нужных конфигураций еще не выполнена. |
| PASS | Фактическое исполнение и доказательство подтверждают все критерии данной конфигурации. |
| FAIL | Фактически наблюдается несоответствие ожидаемому. Укажите шаг, симптом и доказательство. |
| BLOCKED | Попытка остановлена из-за отсутствия безопасного стенда, нужного транспорта или проверяемой фикстуры. Остальные непроверенные подслучаи остаются OPEN. |
