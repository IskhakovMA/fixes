# I‑9 · Краткая матрица HTTP 503 и повторов

База `f849b2909c2d23923e0ce996f0aca4b670ca9c18`. **Исторические случаи объяснены 0/2. Оба остаются UNKNOWN.** Для них отсутствует корреляция запроса, статуса, серверной фазы и исхода транзакции. Все наблюдения ниже получены на синтетических данных либо прямо следуют из контракта маршрута. Штатный публичный отказ Quality v1 сохраняется.

| Граница операции | Наблюдение или контракт | Что известно о данных | Решение о повторе |
|---|---|---|---|
| До COMMIT создания или изменения диагноза | Два синтетических случая SQLite writer contention дали HTTP 503 с одним полем `detail`. Еще один такой 503 получен при отказе обязательного аудита диагноза. | Снимок карты и ее версии либо счетчики создания сохранились. Отдельная проверка аудита диагноза подтвердила сохранность поля и отсутствие новой записи истории. | Явно повторять клиническую запись после восстановления доступа и свежего чтения соответствующей версии. Сохранить тот же ключ и тело там, где API предусматривает идемпотентность. |
| Транзакция выпуска защищенного чтения до COMMIT | Пять HTTP 503 с одним полем `detail` при отказах записи audit или manifest, проверке отсутствующей записи и синтетическом исключении перед COMMIT. | В проверках буфер удержан. Пара audit и manifest отсутствует после отката. Это граница выпуска защищенного чтения. | Выполнить свежее авторизованное чтение после восстановления сервиса с актуальным контекстом и состоянием страницы. Следовать контракту учетной записи, снимка, курсора и прав. |
| Кодированные HTTP 503 | Штатный `QUALITY_NOT_AVAILABLE` для закрытого публичного Quality v1. Например, отказ аудита повтора создания возникает при уже выполненном ранее создании и в данном маршруте возвращается без кода. | Ожидать разрешения или восстановления для закрытого Quality. | Сериализация защищенного ответа до выпуска | В пробе сериализации лабораторного Quality синтетический `ValueError` дал HTTP 503 `QUALITY_READ_UNAVAILABLE`. | Буфер не опубликован. Дельты подтвержденных записей release audit и manifest равны нулю. | Повтор чтения допустим по обычным правилам авторизации и актуальности после восстановления. |
| Рендеринг ответа создания после успешного COMMIT | Синтетический отказ `JSONResponse.render` после создания дал HTTP 500. Самостоятельная проба исключения на границе после COMMIT также дала HTTP 500. | Сохранены одна карточка и одна запись создания. Явный повтор тем же ключом с тем же телом вернул 201 и исходный результат, число карточек осталось неизменным. | Повторять только по контракту конкретного API. Для создания с действительным прежним ключом и тем же телом предусмотрен replay с проверкой прав и обязательным аудитом. Свежий ключ или отсутствие ключа могут создать вторую операцию. |
| Реальная потеря HTTP-подтверждения | Для произвольного сетевого отказа исход COMMIT неизвестен. Браузерные инъекции отдельно моделировали обрыв до отправки и потерю подтверждения после реально сохраненного события. | В контроле было видно, какая фаза выполнена по независимому чтению. Для реального отказа самого клиентского статуса или сообщения об обрыве недостаточно. | Перечитать доступное состояние записи и ее версию через авторизованный запрос. Без документированного replay-контракта решение о новой операции принимает оператор. Автоматический повтор медицинского PATCH запрещен. |

Самостоятельная сверка архива подтвердила восемь наблюдений некодированных 503 в тринадцати HTTP-квитанциях. Это восемь наблюдений в тестовой серии, а не восемь исторических инцидентов. Повтор создания с ключом аудируется заново как replay. Нулевая дельта записи создания не означает отсутствие предусмотренного replay-аудита.
