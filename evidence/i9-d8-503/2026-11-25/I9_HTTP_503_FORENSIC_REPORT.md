# I‑9 — два исторических HTTP 503

**0 из 2 случаев объяснено доказательно. Статус обоих OPEN / UNKNOWN.**

Первоисточник непосредственно скачан из приватного релиза. ZIP прошел CRC, SHA‑256 `d8b887eac3f98303add8ffdf9a86a84192cb2b114eac4062aa6d09fa0104d3e5`. В `http/I8A4_PROCESS_503_DIAGNOSTICS.json` указаны ровно два наблюдения общего HTTP 503 и признаки `historicalOriginEstablished=false`, `historicalFailureReproduced=false`. Отчет I‑8A4, строки 37–39, отдельно описывает контролируемые отказы admission, аудита и commit. Финальное дополнение I‑8A4 повторно оставляет оба исходных случая открытыми. [Исходный ZIP](https://github.com/IskhakovMA/fixes/releases/download/archive-clinic-tracker-2026-11-18/WP_I_I8A4_REVIEW_PACKAGE.zip)

Три задокументированные исторические контрольные пробы использовали SHA `9a431027059c1525bc427fc4a98aa998c8d60fec`, синтетические наборы по 100 пациентов, последовательные процессы A/B, действующую в обоих процессах сессию и прежние inode базы и permit. Каждая дала 200 для собственных капсул и 410 `CURSOR_EXPIRED` для чужих. Для успешных чтений указано по одному manifest, для 410 — ноль. Параллельный запуск на том же каталоге отклонен. Ожидаемый публичный 503 проверялся отдельно. Это история контроля, выполненного на прежнем SHA.

Для двух исходных событий в скачанных материалах нет отдельных квитанций с UTC-временем, маршрутом и методом, идентификатором запроса, формой тела, признаками origin/proxy, серверной фазой и классом исключения, расширенным SQLite-кодом, подтверждением транзакции и отметками аудита. Поэтому сопоставить каждое исходное событие с конкретной ветвью текущего кода невозможно. Сам статус не определяет факт COMMIT. Варианты карты являются гипотезами применительно к историческим случаям.

При новом появлении собирать единый случайный идентификатор и UTC-время, SHA, метод и шаблон маршрута, класс ошибки и безопасный машинный код, фазу commit, итог контрольного чтения через новый connection, дельты аудита/manifest и отдельные статусы proxy и приложения. Использовать только обезличенные признаки, исключить сырые запросы, тела, учетные данные и медицинские идентификаторы. При неизвестном исходе медицинской записи сначала перечитать доступное состояние и версию. Повтор допустим по подтвержденному контракту идемпотентности с тем же ключом либо после явного решения оператора.

Карта источников относится к принятому SHA `f849b2909c2d23923e0ce996f0aca4b670ca9c18`. В рамках этой независимой сверки продуктовые файлы и медицинская база не изменялись. Новые синтетические результаты учитываются в отдельной матрице экспериментов.
