# Заявка на подтверждающую серию P — ожидает решения

**Полный запуск не готов к разрешению сейчас.** Оба кратких окна подтвердили работу инструмента. Требуются оркестрация доказательного запуска, проверка стоп-условий в длинном блоке и утвержденная смесь данных консилиума и селективных фильтров. Ручная D8 и решение владельца открыты.

Продукт `3a0cb5db434032b3f7b6370c305c558a4b5d331c`, SQLite v33, один FastAPI, только 1000 синтетических карточек в каждой отдельной копии. Версия harness определяется Git SHA evidence-коммита и [SHA256SUMS](SHA256SUMS) этого пакета. Перед разрешением зафиксировать подписанную конфигурацию целевого стенда и точные версии браузера, Python, SQLite, Node, Playwright и зависимостей.

| Предлагаемый объем | Значение |
|---|---:|
| Режимы | 4 и 8 активных сессий |
| В каждом режиме | 12 независимых окон по 300 с, 60 с warmup, до 10 с drain |
| Длительность на оба режима | 120 минут измерений, до 28 минут warmup и drain суммарно, плюс создание фикстур и вход |
| Всего измеряемых offered | 21 600 первых GET, 3 600 PATCH, 3 600 открытий карточки, 1 440 workspace и 360 чтений консилиума |
| Предлагаемые пороги | ≥98% своевременных 200 от offered за 2 с, ≤1% обычных 409, ≤1% busy; UI восстановления ≥95% за 2 с после 409 при достаточной выборке |
| Прочие бюджеты | API p50/p95 300/750 мс, реестр 700/1800, карточка 650/1500, клиническая запись 250/650. Ноль нарушений авторизации, целостности и неконтролируемых 503 |

Оценивать каждый режим и обязательные роли отдельно. Единица вариации — независимый блок. Зарегистрировать заранее блоковый bootstrap из исходного протокола и число измерений восстановления. Отказ по целостности, неизвестный COMMIT, неконтролируемый 503 или нарушение учтенного расписания останавливают серию. Сохранять исходный результат, а причину и повтор оформлять отдельно. При недостатке естественных 409 функциональная проверка остается полезной и не объединяется с UX SLO.

Требования к среде: выделенный хост, место для независимых SQLite-копий и защищенных локальных квитанций, достаточный запас CPU и памяти для восьми Chromium-контекстов, синхронизированные UTC и монотонные таймеры, отдельный контроль генератора. Утвердить абсолютные ресурсы после инструментального preflight на целевой машине. Полный orchestrator 24 окон, заранее закрепленный порядок, кластерный расчет и контроль устойчивости генератора в продолжительных окнах требуют отдельного preflight. Текущий локальный supervisor намеренно ограничен короткими окнами.
