## Оператор

1. Запустите подготовленный локальный launcher. На другом Mac возьмите исходный комплект и 16 шагов по ссылкам. Используйте отдельный чистый checkout точного B1 и Python 3.13 с пакетами из его lock. Подставьте абсолютные пути. Каталог результата должен быть локальным, закрытым для других пользователей и вне Git. [Комплект синтетического стенда](https://github.com/IskhakovMA/fixes/tree/2733592fae05468ce8206c6a9900d3adaec606b5/evidence/i9-b1-extended-investigation/d8)

   ```bash
   "$B1_PYTHON" -I -B d8_mac_session.py --app "$B1_CHECKOUT" \
     --kit "$D8_KIT" --steps "$D8_STEPS" --output "$PRIVATE_OUTPUT"
   ```

2. Runner проверит байты опубликованного комплекта, наличие Safari/VoiceOver, поднимет одноразовую синтетическую SQLite и откроет в Safari только готовый loopback URL. Перед запуском выберите выделенный профиль Safari без синхронизации и расширений. Включите VoiceOver, включите Tab по всем элементам и убедитесь, что слышите озвучивание. Синтетические учетные данные берите из временной приватной фикстуры, показанной в терминале.
3. Следуйте шагам в терминале. На подслучае в каждой теме выберите P, F, B или N. Для результатов P/F укажите сокращенное услышанное объявление, видимый фокус, фактическое действие и исход, роль, ширину, нативный масштаб, клавиатурные настройки и наблюдаемые записи. Строка получает PASS только при PASS всех обязательных подслучаев. Недоступный нативный зум, отказ или транспорт оставляйте открытым с точной причиной. Для сценария, требующего свежей синтетической фикстуры после изменений, завершите сеанс и запустите новый с параметром `--start-scenario` и его ID. Сопоставьте квитанции разных сеансов по версии продукта, сценарию, теме и подслучаю.
4. Для остановки после записи используйте Q или Ctrl+C. Проверьте признак `verifiedShutdown` в частной итоговой квитанции. Runner завершает сервер и проверяет освобождение порта и удаление временной SQLite и фикстуры. Он не записывает аудио, экран или HTTP-дампы. Частные JSON и JSONL требуют отдельной проверки содержания человеком. При публикации удалите логины, идентификаторы, локальные пути, параметры URL, клинические поля и все чувствительные сведения. Проверка формата ввода сама по себе не гарантирует обезличивание.

## Автоматические проверки

Режим `--technical-check` выполняет технический запуск и чистую остановку без открытия Safari. Режим `--keyboard-check` использует локально установленный Playwright и Chromium, проверяет skip link, именование панели, стрелки, Home/End и клавиатурный переход в обеих темах. Разрешен только loopback origin. В счетчиках отдельно отражается штатное продление сессии от клавиатуры. Срабатывание автоматической проверки не подтверждает реальное озвучивание в Safari. Технический запуск сохранен в [квитанции](D8_TECHNICAL_START_STOP.json), тесты проверки комплектности — в [результатах самопроверки](D8_OPERATOR_SELF_TESTS.json).

## Фактический прогон на B1

Chromium 151.0.7922.34 прошел обе темы на реальном loopback FastAPI. В каждой теме подтверждены переход skip link, фокус и выбранность после стрелок и Home/End, связь вкладки и панели, выход по Tab и возврат по Shift+Tab. Зарегистрирована одна штатная операция активности сессии на тему. Клинических мутаций, внешних запросов и ошибок страницы — ноль. Синтетическая база и порт очищены. [Машинный результат Chromium](D8_KEYBOARD_CHROMIUM.json)

Первичные попытки проверки клавиатуры остановились до навигации: Playwright ожидал установленную ревизию Chromium из другого локального кеша. После выбора имеющегося совместимого Chromium диагностический счетчик ошибочно отнес штатный POST активности сессии к медицинским записям. Исправление учитывает этот точный маршрут отдельно и продолжает требовать ноль остальных мутаций. Для всех попыток подтверждена штатная остановка. Итоговые ручные статусы прежние.
