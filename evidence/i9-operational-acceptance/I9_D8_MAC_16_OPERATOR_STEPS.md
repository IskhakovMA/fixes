# D8 B1 — 16 последовательных проверок в Safari с VoiceOver

Точный продуктовый SHA — `3a0cb5db434032b3f7b6370c305c558a4b5d331c`. Сценарии и критерии соответствуют [руководству PR №12 на точном коммите](https://github.com/IskhakovMA/fixes/blob/f02400c16139293b8470f5c03bbafe1293b2a69c/evidence/i9-d8-503/2026-11-25/I9_D8_MAC_OPERATOR_GUIDE.md). Новый стенд прошел техническую проверку на B1. Все 16 исходных Mac-квитанций начинаются с `NOT TESTED`.

## Перед первым шагом

1. Запустите стенд по README и откройте URL, который указал launcher. В чистом профиле Safari отключите синхронизацию и расширения. Учетные данные синтетической фикстуры доступны только из показанного пути в приватном терминале. Сверьте роль `doctor`, `head`, `hiddenDoctor` или `developer` по шагу. Для стандартных шагов возьмите доступную карточку «Синтетика I8A3 00000».
2. Включите VoiceOver лично через Command+F5. В Safari включите переход Tab по всем элементам веб-страницы. Сверяйте положение Tab-фокуса и курсора VoiceOver отдельно. Используйте VO+стрелки для чтения, VO+Shift+Down/Up для входа в группу и выхода, VO+Space для активации. Отключите Quick Nav для проверки, если он перехватывает стрелки. Отдельно послушайте rotor landmarks и выбор вкладки.
3. Выполните шаги 1–16 по порядку. Для каждого повторенного сочетания роли, темы, масштаба, reduced motion, ширины и DPR создайте отдельную строку `subcase` в локальной копии `I9_D8_MAC_SESSION_RECEIPTS.tsv`. Проверяйте обе темы. Проводите записи только в явно предусмотренных шагах и только над одноразовой синтетической записью. После изменений прав или базы, влияющих на следующий шаг, остановите стенд и запустите свежую фикстуру.
4. Впишите фактические build OS/Safari/VoiceOver, дату и время UTC, нейтральную метку фикстуры, услышанные названия и сообщения, последовательность фокуса и ожидаемое/фактическое число медицинских записей. Допустимо фиксировать тип операции, HTTP-статус и число. Обычная навигация означает ноль медицинских записей. В ответах избегайте имен, идентификаторов, маршрутов с ID, паролей, cookies, HAR и тел запросов. Нужный статус или подслучай, который не удалось фактически наблюдать, остается OPEN в записи подслучая. Саму основную строку сохраняйте NOT TESTED либо BLOCKED согласно причине. PASS требует личного выполнения всех критериев строки, FAIL требует наблюдаемого расхождения.

## Особые условия

- Для шага D8-QUALITY-01 откройте внутреннюю лабораторию только на подтвержденном loopback URL и под синтетической ролью developer. После проверки `syntheticOnly` и `qualityPath` локальной фикстуры используйте штатную настройку `setupBounded()` из `tools/tests/wp_i_quality/browser_helpers.cjs`, включая `app.mountQualityV1('/api/_i8a3_lab')` в консоли того же документа. Закройте инспектор перед проверкой. Для каждого реально доступного нативного масштаба 100%, 200%, 400% запишите точное значение из меню Safari и фактическую CSS-ширину. Если Safari не предоставляет значение, оставьте соответствующий подслучай OPEN.
- Для D8-LOSS-01 и D8-SESSION-01 проверьте, что нужный тестовый сбой действительно наблюдался. Воспроизведение не должно затрагивать сеть рабочей установки. Не создавайте открытых сетевых маршрутов. Если послезапросная потеря связи, консилиумный слот, серверный 401/404 или управление задержкой 200 не подготовлены на синтетическом стенде, подслучай остается открытым. В D8-DRAFT-01 для реального 409 нужны две независимые синтетические сессии.
- После заполнения квитанций завершите стенд одним Ctrl+C из его терминала. Техническая квитанция с `cleanExit`, `listenerClosed` и `scratchRemoved` подтверждает остановку стенда. Убедитесь, что ручные результаты записаны в отдельной копии TSV. Launcher оставляет их без изменений.
