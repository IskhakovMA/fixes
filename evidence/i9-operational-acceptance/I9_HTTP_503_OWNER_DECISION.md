# I-9. Выбор владельца по двум историческим HTTP 503

**Статус документа — на утверждение. Решение и подпись отсутствуют.** Объяснено **0/2**, оба случая остаются **OPEN / UNKNOWN** при любом выборе. Для исходных событий отсутствует корреляция запроса, ответа, серверного источника и результата COMMIT. Результаты современных синтетических проверок помогают установить границы риска. Исторические причины от этого не установлены. [Разбор и матрица PR №12](https://github.com/IskhakovMA/fixes/blob/f02400c16139293b8470f5c03bbafe1293b2a69c/evidence/i9-d8-503/2026-11-25/I9_HTTP_503_DECISION_MATRIX.md) · [Замечания владельца](https://github.com/IskhakovMA/fixes/pull/12#pullrequestreview-6056658922)

| Вариант | Решение владельца | Условие пересмотра |
|---|---|---|
| **A. Сохранить блокировку** | Оба случая остаются открытым риском. Этот пункт блокирует рассмотрение отдельного Draft PR B1. Сохраняются остальные технические и ручные этапы приемки. | Новые первичные данные с достаточной корреляцией либо новое явное решение владельца о компенсирующих мерах. Повторять старую форензику без новых данных не требуется. |
| **B. Условно принять остаточный риск** | Разрешить учитывать этот риск как условно принятый только при рассмотрении Draft PR для указанного ниже точного SHA. Назначить ответственного, утвердить процедуру работы с неизвестным COMMIT, эскалацию и срок пересмотра. Оба события остаются UNKNOWN. | По истечении срока, при изменении проверяемого продукта или процедуры либо после нового некодированного 503 с неопределенным исходом медицинской записи вернуть этот пункт в OPEN и вынести на повторное решение. |

При выборе B остальные условия Draft PR, включая профиль и критерии производительности, D8 и отдельное разрешение на открытие PR, сохраняются. Ни один вариант не разрешает merge, пилот с реальными данными или production.

## Процедура для варианта B

1. При неизвестном исходе клинической записи остановить повтор и выполнить свежее авторизованное чтение состояния и версии.
2. Явный replay допустим только по документированному контракту конкретного маршрута с прежними действующим ключом, телом и контекстом операции. Автоматический повтор клинических PATCH и POST исключен.
3. Если исход остается неизвестным, права изменились или обнаружено расхождение состояния и обязательного аудита, прекратить запись и передать случай назначенному ответственному. Новый некодированный 503 на клинической записи с неизвестным COMMIT открывает отдельный инцидент.
4. Для будущей диагностики отдельно утвердить безопасные метаданные и хранение. Случайный корреляционный ID, UTC, SHA сборки, шаблон маршрута, коды приложения и proxy, подтвержденные стадии COMMIT/rollback/unknown, состояние audit/manifest и стадия доставки ответа. Медицинские идентификаторы, тела, SQL и секреты исключаются.
